# Доменные агрегаты (Domain Aggregates)

## 1. Медицинский домен (Patient Care Context)

### Агрегат Patient (Пациент)
**Корень агрегата:** Patient
**Границы:** Включает персональные данные, контактную информацию, медицинскую историю
**Инварианты:**
- Уникальный идентификатор пациента
- Обязательные поля: ФИО, дата рождения, пол
- Согласие на обработку персональных данных

**Сущности:**
- PersonalInfo (персональная информация)
- ContactInfo (контактная информация)
- MedicalHistory (медицинская история)
- Consent (согласие на обработку данных)

**Доменные события:**
- PatientRegistered
- PatientDataUpdated
- ConsentWithdrawn

### Агрегат Appointment (Приём)
**Корень агрегата:** Appointment
**Границы:** Включает запись на приём, расписание, отмены
**Инварианты:**
- Время приёма не может быть в прошлом
- Один врач не может быть в двух местах одновременно
- Пациент должен быть зарегистрирован

**Сущности:**
- Schedule (расписание)
- Doctor (врач)
- TimeSlot (временной слот)
- Cancellation (отмена)

**Доменные события:**
- AppointmentScheduled
- AppointmentCancelled
- AppointmentRescheduled
- AppointmentCompleted

### Агрегат Treatment (Лечение)
**Корень агрегата:** Treatment
**Границы:** Включает лечебный процесс, назначения, результаты
**Инварианты:**
- Лечение должно быть связано с пациентом
- Назначения должны быть валидными
- Результаты должны соответствовать назначениям

**Сущности:**
- Prescription (назначение)
- Procedure (процедура)
- Result (результат)
- FollowUp (наблюдение)

**Доменные события:**
- TreatmentStarted
- PrescriptionCreated
- TreatmentCompleted
- FollowUpScheduled

### Агрегат MedicalRecord (Медкарта)
**Корень агрегата:** MedicalRecord
**Границы:** Включает все медицинские документы и записи
**Инварианты:**
- Медкарта должна быть связана с пациентом
- Записи должны быть подписаны врачом
- История изменений должна сохраняться

**Сущности:**
- Document (документ)
- Entry (запись)
- Signature (подпись)
- Version (версия)

**Доменные события:**
- MedicalRecordCreated
- MedicalRecordUpdated
- MedicalRecordSigned
- MedicalRecordArchived

## 2. Финтех домен (Financial Services Context)

### Агрегат Account (Счёт)
**Корень агрегата:** Account
**Границы:** Включает банковский счёт, баланс, операции
**Инварианты:**
- Баланс не может быть отрицательным без овердрафта
- Все операции должны быть валидными
- Счёт должен быть связан с клиентом

**Сущности:**
- Balance (баланс)
- Transaction (транзакция)
- Overdraft (овердрафт)
- Interest (проценты)

**Доменные события:**
- AccountCreated
- BalanceUpdated
- TransactionProcessed
- OverdraftActivated

### Агрегат Payment (Платёж)
**Корень агрегата:** Payment
**Границы:** Включает платёжную транзакцию, статус, комиссии
**Инварианты:**
- Сумма платежа должна быть положительной
- Платёж должен иметь получателя
- Статус должен быть валидным

**Сущности:**
- Amount (сумма)
- Recipient (получатель)
- Status (статус)
- Fee (комиссия)

**Доменные события:**
- PaymentInitiated
- PaymentProcessed
- PaymentFailed
- PaymentRefunded

### Агрегат Credit (Кредит)
**Корень агрегата:** Credit
**Границы:** Включает кредитный продукт, заявку, погашение
**Инварианты:**
- Кредит не может превышать лимит
- Платежи должны соответствовать графику
- Статус должен быть валидным

**Сущности:**
- Application (заявка)
- Terms (условия)
- Schedule (график платежей)
- Collateral (залог)

**Доменные события:**
- CreditApplicationSubmitted
- CreditApproved
- CreditDisbursed
- PaymentReceived

### Агрегат Card (Карта)
**Корень агрегата:** Card
**Границы:** Включает банковскую карту, лимиты, операции
**Инварианты:**
- Карта должна быть связана со счётом
- Лимиты должны быть валидными
- Статус карты должен быть актуальным

**Сущности:**
- CardInfo (информация о карте)
- Limits (лимиты)
- Usage (использование)
- Security (безопасность)

**Доменные события:**
- CardIssued
- CardActivated
- CardBlocked
- LimitExceeded

## 3. AI-сервисы домен (Intelligent Diagnostics Context)

### Агрегат Model (ML модель)
**Корень агрегата:** Model
**Границы:** Включает ML модель, версионирование, метрики
**Инварианты:**
- Модель должна иметь версию
- Метрики должны быть валидными
- Модель должна быть обучена

**Сущности:**
- Version (версия)
- Metrics (метрики)
- Artifacts (артефакты)
- TrainingData (данные обучения)

**Доменные события:**
- ModelTrained
- ModelDeployed
- ModelRetired
- MetricsUpdated

### Агрегат Prediction (Предсказание)
**Корень агрегата:** Prediction
**Границы:** Включает предсказание модели, входные данные, результат
**Инварианты:**
- Предсказание должно быть связано с моделью
- Входные данные должны быть валидными
- Результат должен быть в допустимом диапазоне

**Сущности:**
- InputData (входные данные)
- Result (результат)
- Confidence (уверенность)
- Explanation (объяснение)

**Доменные события:**
- PredictionRequested
- PredictionGenerated
- PredictionValidated
- PredictionExplained

### Агрегат Diagnosis (Диагноз)
**Корень агрегата:** Diagnosis
**Границы:** Включает AI диагноз, обоснование, рекомендации
**Инварианты:**
- Диагноз должен быть связан с пациентом
- Обоснование должно быть предоставлено
- Рекомендации должны быть валидными

**Сущности:**
- Condition (состояние)
- Evidence (обоснование)
- Recommendation (рекомендация)
- Confidence (уверенность)

**Доменные события:**
- DiagnosisRequested
- DiagnosisGenerated
- DiagnosisValidated
- RecommendationProvided

## 4. Фармацевтический домен (Pharmaceutical Management Context)

### Агрегат Drug (Лекарство)
**Корень агрегата:** Drug
**Границы:** Включает лекарственный препарат, характеристики, взаимодействия
**Инварианты:**
- Лекарство должно иметь уникальный код
- Характеристики должны быть валидными
- Взаимодействия должны быть задокументированы

**Сущности:**
- DrugInfo (информация о лекарстве)
- Composition (состав)
- Interactions (взаимодействия)
- Contraindications (противопоказания)

**Доменные события:**
- DrugAdded
- DrugUpdated
- InteractionDetected
- ContraindicationFound

### Агрегат Inventory (Запас)
**Корень агрегата:** Inventory
**Границы:** Включает запасы лекарств, остатки, сроки годности
**Инварианты:**
- Остаток не может быть отрицательным
- Срок годности должен быть валидным
- Запас должен быть связан с аптекой

**Сущности:**
- Stock (остаток)
- ExpiryDate (срок годности)
- Location (местоположение)
- Batch (партия)

**Доменные события:**
- InventoryUpdated
- StockLow
- ExpiryWarning
- BatchReceived

### Агрегат Prescription (Рецепт)
**Корень агрегата:** Prescription
**Границы:** Включает рецепт, назначения, выполнение
**Инварианты:**
- Рецепт должен быть выписан врачом
- Назначения должны быть валидными
- Выполнение должно соответствовать назначению

**Сущности:**
- PrescriptionInfo (информация о рецепте)
- Medications (лекарства)
- Dosage (дозировка)
- Instructions (инструкции)

**Доменные события:**
- PrescriptionCreated
- PrescriptionFilled
- PrescriptionCancelled
- DosageAdjusted

### Агрегат Sale (Продажа)
**Корень агрегата:** Sale
**Границы:** Включает продажу лекарств, оплату, документооборот
**Инварианты:**
- Продажа должна быть связана с рецептом
- Оплата должна быть подтверждена
- Документы должны быть оформлены

**Сущности:**
- SaleInfo (информация о продаже)
- Payment (оплата)
- Receipt (чек)
- Customer (покупатель)

**Доменные события:**
- SaleInitiated
- SaleCompleted
- PaymentReceived
- ReceiptGenerated

## 5. Оборудование домен (Medical Equipment Context)

**Корень агрегата:** Equipment
**Границы:** Включает медицинское оборудование, характеристики, статус
**Инварианты:**
- Оборудование должно иметь уникальный серийный номер
- Характеристики должны быть валидными
- Статус должен быть актуальным

**Сущности:**
- EquipmentInfo (информация об оборудовании)
- Specifications (характеристики)
- Status (статус)
- Location (местоположение)

**Доменные события:**
- EquipmentRegistered
- EquipmentMoved
- EquipmentStatusChanged
- EquipmentRetired

### Агрегат Maintenance (Обслуживание)
**Корень агрегата:** Maintenance
**Границы:** Включает плановое и аварийное обслуживание
**Инварианты:**
- Обслуживание должно быть связано с оборудованием
- Планы должны быть выполнимыми
- Результаты должны быть задокументированы

**Сущности:**
- MaintenancePlan (план обслуживания)
- Task (задача)
- Result (результат)
- Technician (техник)

**Доменные события:**
- MaintenanceScheduled
- MaintenanceStarted
- MaintenanceCompleted
- MaintenanceFailed

### Агрегат Telemetry (Телеметрия)
**Корень агрегата:** Telemetry
**Границы:** Включает телеметрические данные, мониторинг, алерты
**Инварианты:**
- Данные должны быть связаны с оборудованием
- Временные метки должны быть валидными
- Значения должны быть в допустимом диапазоне

**Сущности:**
- SensorData (данные датчиков)
- Metrics (метрики)
- Alert (алерт)
- Threshold (порог)

**Доменные события:**
- TelemetryReceived
- ThresholdExceeded
- AlertTriggered
- AnomalyDetected

### Агрегат Incident (Инцидент)
**Корень агрегата:** Incident
**Границы:** Включает инциденты, отказы, расследования
**Инварианты:**
- Инцидент должен быть связан с оборудованием
- Приоритет должен быть валидным
- Статус должен соответствовать жизненному циклу

**Сущности:**
- IncidentInfo (информация об инциденте)
- Priority (приоритет)
- Investigation (расследование)
- Resolution (решение)

**Доменные события:**
- IncidentReported
- IncidentAssigned
- IncidentResolved
- PostMortemCompleted

**Корень агрегата:** DataProduct
**Границы:** Включает продукт данных, метаданные, SLA
**Инварианты:**
- Продукт должен иметь владельца
- Метаданные должны быть полными
- SLA должны быть выполнимыми

**Сущности:**
- ProductInfo (информация о продукте)
- Metadata (метаданные)
- SLA (соглашение об уровне сервиса)
- Quality (качество)

**Доменные события:**
- DataProductCreated
- DataProductUpdated
- SLAViolated
- QualityDegraded

**Инварианты:**
- Событие должно иметь валидную схему

**Сущности:**
- EventData (данные события)

**Доменные события:**

## 7. Портал самообслуживания (Self-Service Analytics Context)

### Агрегат Dashboard (Дашборд)
**Корень агрегата:** Dashboard
**Границы:** Включает дашборд, виджеты, настройки
**Инварианты:**
- Дашборд должен иметь владельца
- Виджеты должны быть валидными
- Настройки должны быть применимыми

**Сущности:**
- DashboardInfo (информация о дашборде)
- Widgets (виджеты)
- Layout (макет)
- Permissions (разрешения)

**Доменные события:**
- DashboardCreated
- DashboardShared
- WidgetAdded
- LayoutChanged

### Агрегат Report (Отчёт)
**Корень агрегата:** Report
**Границы:** Включает отчёт, параметры, выполнение
**Инварианты:**
- Отчёт должен иметь определение
- Параметры должны быть валидными
- Выполнение должно быть отслеживаемым

**Сущности:**
- ReportDefinition (определение отчёта)
- Parameters (параметры)
- Execution (выполнение)
- Output (результат)

**Доменные события:**
- ReportScheduled
- ReportExecuted
- ReportCompleted
- ReportFailed

### Агрегат Query (Запрос)
**Корень агрегата:** Query
**Границы:** Включает SQL запрос, выполнение, результаты
**Инварианты:**
- Запрос должен быть синтаксически корректным
- Выполнение должно быть безопасным
- Результаты должны быть валидными

**Сущности:**
- QueryText (текст запроса)
- Execution (выполнение)
- Result (результат)
- Performance (производительность)

**Доменные события:**
- QuerySubmitted
- QueryExecuted
- QueryCompleted
- QueryOptimized
